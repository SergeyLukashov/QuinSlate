# QuinSlate 1.0.3

> _Last updated: 2026-11-09_

Released from `v1.0.2..a1ef32d` (2 commits; the manifest bump to `1.0.3.0` is in the
working tree, not yet committed).

## User-facing

- **Search across all five slates** (`e57a1e1`). Ctrl+F opens a floating pill over the
  top-right of the editor; the query runs against every slate at once, page-side, where
  all five CodeMirror states already live. Nothing is written to the document and there
  is no replace. Spec `Docs/Specs/24-SEARCH.md`; keyboard additions recorded in
  `Docs/Specs/06-KEYBOARD-NAV.md`; queue entry 24 closed.
  - Matching is tiered, chosen globally across slates: phrase, then all words in any order
    on one line, then typo-tolerant (bounded Damerau-Levenshtein against word starts, 1 edit
    from 4 letters, 2 from 8). Folding drops case, accents, typographic punctuation,
    whitespace runs and hidden markdown markers, so `ship friday` finds `Ship **Friday**`.
    Pure modules: `build/src/searchFold.js`, `searchMatch.js`, `fuzzyDistance.js`,
    `searchWalk.js`, all with `node --test` coverage; `search.js` holds the cross-slate state
    and `searchHighlight.js` the `.cm-search-match`/`.cm-search-current` decorations.
  - Per-line fold cache built ahead of the first query in 8 ms `requestIdleCallback`
    slices; matches cached per slate and tier; queries coalesced to one per frame. No
    typing debounce.
  - Host side: `Components/SearchPillView.xaml` (+ `.xaml.cs`), `SearchController.cs`,
    `EditorSearchChannel.cs` for the `searchQuery`/`searchStep`/`searchClose` bridge
    messages, and `SearchCounterFormatter.cs` for `2 of 6` / `6 results` / `≈ 1 of 3` /
    `No results` / `9,999+`. The counter is a UIA live region (`LiveRegionAnnouncer.cs`).
  - Tab badges: an `InfoBadge` on `TabHeaderView.SearchBadge`, tinted by default and solid
    on the current match's tab, animated by `SearchBadgeMotion.cs`.
    `TabStripCalculator.ComputeTitleMaxWidth` gained a `badgeWidth` term so the title
    ellipsizes before the badge truncates.
  - Keys: Enter/Shift+Enter in the box and F3/Shift+F3 step in tab-strip order (so they
    follow a drag-reorder), wrapping 5 to 1. F3 with the pill closed reopens on the last
    query. Esc closes and turns the current match into the selection. Ctrl+F seeds from a
    single-line selection of up to 256 characters, markers stripped (`panelShortcuts.js`).
  - `searchSpacer.js` adds an eased top spacer and scroll margin while the pill is open so
    it never hides a match or traps the top of a slate; `buffers.js` stores the spacer
    height with each slate's scroll snapshot to realign on tab switch.
  - Panel hide closes the search (`MainWindow.xaml.cs` calls `Panel.CloseSearch()`). The
    query is never persisted and, like buffer text, never logged: `searchQuery` and the
    Ctrl+F `seed` on `key` join the bridge's no-log list in `CLAUDE.md` and
    `Docs/Wiki/06-WEB-EDITOR-BUNDLE.md`.

## Internal

- `e57a1e1` **`BufferPanel` split up.** `Views/BufferPanel.xaml.cs` dropped from 1,687
  lines to 437, its responsibilities moved into `Components/`:
  `BufferTabStrip`, `TabStripLayout`, `TabContextMenu`, `TabLabelEditor`,
  `TabHeaderRegistry`, `EditorPane`, `EditorOverlayPositioner`, `PanelBackgroundPainter`,
  `StartupCoverController`, plus `Models/TabOrder.cs` and `Services/TabDefinitionStore.cs`
  (both newly unit-tested). `EditorHost` shed `EditorBridgeJson`, `EditorKeyCommandRouter`,
  `EditorLinkLauncher`, `EditorThemeColors` and `EditorWebViewSettings`. The limit
  notice's hand-rolled shadow and slide-in are now shared with the search pill as
  `PillDropShadow` and `PillMotion`. No behaviour change intended; wiki pages 01 and 05 and
  Investigation 07 updated to the new member names.
- `a1ef32d` Dependency bumps: Windows App SDK 2.4.0 to 2.6.5, SDK build tools to
  10.0.28000.2957, SkiaSharp 4.155.0, xunit.v3 4.0.3, plus patch releases of the test SDK,
  runner and coverlet. No behaviour change.
